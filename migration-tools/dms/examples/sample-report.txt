4. SOURCE DATABASE SIZE QUERIES (run on the source database)
==============================================================================
DMS reports row counts only, so these read-only queries fill the gap: row
counts, average row bytes, and average row size as a JSON document.
Replace <schema>.<table> where present; samples read 1000 rows.

postgres, all tables:
  SELECT schemaname, relname, n_live_tup AS row_count,
         pg_table_size(relid) / NULLIF(n_live_tup, 0) AS avg_row_bytes
  FROM pg_stat_user_tables ORDER BY pg_table_size(relid) DESC;
postgres, average JSON bytes per row (run per table):
  SELECT avg(octet_length(to_jsonb(t)::text))::int AS avg_json_bytes
  FROM (SELECT * FROM <schema>.<table> LIMIT 1000) t;

Note: the JSON figures measure each row serialized as a document, which is
how change events are sized. They exceed avg_row_bytes because column names
repeat in every row and numbers and dates serialize as text.
Total JSON GB ~= row_count x avg_json_bytes.
